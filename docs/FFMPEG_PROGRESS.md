# FFmpeg stream progress

The external FFmpeg downloader does not emit yt-dlp's normal percentage/ETA lines.
The existing Android library returns its last parsed percentage for unrecognized
stdout lines. Adding `--progress` alone therefore does not produce useful progress.

The downloader now adds FFmpeg's documented `-progress pipe:1` stdout protocol.
It retains `-loglevel error -nostats`, the trusted CA bundle, TLS verification,
existing format selection, stream copy, session extraction, and output paths.

The same extraction prints only duration/live-state metadata before each item.
No second metadata HTTP request, signed media URL, cookie, or header dump is needed.
`FfmpegProgressTracker` handles `out_time_us`, legacy microsecond `out_time_ms`,
clock fallback, and `total_size`. Updates are delivered on `progress=continue/end`.
Playlist metadata resets the tracker. Percentages are based on media time, not
guessed bitrate/byte size, and cap at 99 until the existing artifact verification
and MediaStore export finish. Live/unknown-duration streams show elapsed media
time and bytes, not a fabricated percentage.

## Tests

JVM tests cover durations, microsecond units, malformed/N/A fields, clock fallback,
playlist resets, unrelated lines, live streams, and verified-completion boundaries.

An isolated test-only instrumentation runner generates a 12-second blue MP4 using
the bundled FFmpeg, serves it over the emulator's loopback HTTPS socket, and downloads
it through the real YoutubeDL/FFmpeg callback pipeline. It applies the resulting
snapshots to the real MainActivity progress/notification UI, verifies intermediate
percentages and 99% finalization, exports the file using the production publisher,
checks nonzero size/video track/duration, then verifies 100% completion.
The test-only TLS certificate/key are generated by the installed JDK keytool into
ignored build outputs, never committed or included in the production APK. FFmpeg
verifies the server with the generated test CA. Controlled `--load-info-json`
metadata avoids site authentication and an extra extractor request; the real
duration print template and FFmpeg callback/output pipeline are used unchanged.
Its explicit 12-second intermediate hold is for capturing a real progress screen.
The runner also checks matching notification progress when permission is enabled,
unknown-duration indeterminate UI, and stopping the animation when the job ends.
Only the test's own synthetic MediaStore export is removed; login cookies,
preferences, existing user downloads, and access-control settings are untouched.
The test APK is never included in the production APK or release assets.

```powershell
gradle --no-daemon -PtargetAbi=x86_64 testDebugUnitTest assembleDebug assembleDebugAndroidTest
adb -s emulator-5554 install -r app/build/outputs/apk/debug/app-debug.apk
adb -s emulator-5554 install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s emulator-5554 shell am instrument -w com.local.ytdown.test/com.local.ytdown.StreamProgressInstrumentation
```

This proves the FFmpeg progress pipeline with owned media, not any particular
site's current authentication/network behavior. Site-specific progress still
depends on the extractor supplying duration; unknown duration remains indeterminate.
