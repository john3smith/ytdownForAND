# HTTPS 연결 보조

일부 HTTPS 연결의 초기 TLS 핸드셰이크를 분할 전송하는 선택 기능입니다.
특정 사이트의 다운로드 지원 여부나 모든 차단 환경에서의 성공을 보장하지 않습니다.

- 최초 기본값은 OFF이며 사용자가 선택한 상태만 로컬 설정에 저장합니다.
- 로그인 화면 진입 시점, 다운로드 대기열 등록 시점의 설정을 사용합니다.
- 실행 중인 다운로드는 나중에 토글을 변경해도 연결 방식을 바꾸지 않습니다.
- 앱의 허용된 HTTPS 호스트만 처리하고 다른 사이트 및 다른 앱의 통신은 변경하지 않습니다.
- 별도 VPN 권한, 외부 프록시 서버, 외부 계정이나 외부 DNS를 추가하지 않습니다.

## 구조와 보안

앱 프로세스 안에 임시 `127.0.0.1` CONNECT 중계를 생성합니다. HTTPS 443 및
허용된 도메인만 받을 수 있으며, 사설/루프백/예약 IP로의 연결은 거절합니다.
연결 수, 헤더 크기, TLS 레코드 크기, 연결 및 유휴 시간을 제한합니다.
사용자가 없으면 리스너와 소켓을 닫습니다.

처음의 평문 ClientHello를 SNI 호스트명 중간에서 두 TLS 레코드로 나누되,
핸드셰이크 메시지 바이트는 변경하지 않습니다. 이후 데이터는 암호화된 상태로
중계합니다. TLS를 종료하거나 해독하지 않으며 사용자 인증서를 설치하지 않습니다.
기존 클라이언트의 인증서/호스트명 검증을 비활성화하지 않습니다.
패킷 내용, 쿠키, 비밀번호 및 HTTP 응답 본문을 중계 로그에 기록하지 않습니다.

WebView에는 공식 `ProxyController`의 reverse bypass 기능을 사용합니다.
두 프록시 기능을 지원하지 않는 WebView에서는 안내를 표시하고 자동으로
전체 앱 프록시나 인증서 무시 방식으로 대체하지 않습니다. 로그인 화면 종료 시
WebView 프록시 설정을 해제합니다.
다운로드 엔진에는 해당 작업에만 `--proxy`를 전달합니다.

나이 확인, 로그인, CAPTCHA, 접근 권한 제한은 그대로 유지합니다.
사용자가 확인하지 않은 게스트 세션을 로그인 완료로 저장하지 않습니다.
인증이 필요한 작업은 앱에서 정상적으로 저장된 세션이 있어야 실행됩니다.

## 제한

DNS/IP 차단, TLS 레코드 재조립을 지원하는 필터, 서버 측 접속 거부,
지역별 제한, 계정 제한, 브라우저 TLS 호환성 문제를 모두 해결하지는 못합니다.
기존 다운로드 엔진에 브라우저 impersonation 의존성이 없으면 그 경고는
이 기능과 별도로 남을 수 있습니다. 로컬 테스트에서 페이지 접속이 성공했다고
실제 미디어 다운로드까지 성공한 것으로 취급하지 않습니다.

## 검증

도메인 경계, CONNECT 제한, 사설 IP 거절, TLS 레코드 파싱/분할/손상 입력,
핸드셰이크 및 후속 바이트 무결성, 리스너 종료, 대기열별 설정 고정에 대해
JUnit 테스트를 포함합니다. 실제 사이트 인증과 미디어 저장은 별도로
Android Emulator에서 검증하며 사용자 확인이 필요한 단계에서는 중단합니다.

참고: [TLS 1.3 레코드 규칙](https://datatracker.ietf.org/doc/html/rfc8446#section-5.1),
[AndroidX ProxyController](https://developer.android.com/reference/androidx/webkit/ProxyController).
