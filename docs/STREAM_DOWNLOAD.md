# 스트리밍 저장 경로

일부 세션 기반 영상 경로는 기존 추출기로 미디어를 한 번만 확인한 뒤,
앱에 번들된 FFmpeg 외부 다운로더로 저장합니다. 페이지 HTML 자체를
FFmpeg에 전달하지 않으며 광고 영상이나 임의의 브라우저 네트워크 요청을
자동 수집하지 않습니다.

## 처리 순서

1. 사용자가 등록한 링크와 작업 등록 시점의 영상/음원·화질·HTTPS 연결 보조 설정을 사용합니다.
2. 기존 로그인 저장소가 내보낸 쿠키를 동일한 취소 가능한 추출/다운로드 작업에 전달합니다.
3. 영상 모드의 대상 경로에만 `--downloader ffmpeg`를 적용합니다. 해당 경로는 선택한 화질 제한을 지키며 영상·음성이 합쳐진 형식을 우선 사용합니다. 다른 사이트와 M4A 추출은 기존 경로를 유지합니다.
4. 기존 로컬 연결 보조가 선택됐다면 그 프록시를 사용합니다. 연결 보조의 기본값은 여전히 OFF입니다.
5. FFmpeg는 신뢰 CA 파일과 `-tls_verify 1`을 사용합니다. 인증서 파일이나 FFmpeg 실행 파일이 없으면 실패로 처리하며 검증을 끄지 않습니다.
6. 최종 `after_move` 이벤트의 JSON 파일 경로를 검증합니다. 다운로드 폴더 밖의 경로, 빈 파일, 사진, `.part`는 완료된 영상으로 인정하지 않습니다.
7. Android 10 이상에서는 앱 내부 캐시에서 완성한 영상을 `MediaStore.Downloads`의 `Download/YTDown`에 복사합니다. `IS_PENDING`으로 복사 중 파일을 숨기고, 크기와 SHA-256 확인 후 공개합니다. 전체 파일 접근 권한을 요구하지 않습니다.

내부 임시 파일은 앱 캐시이며 Android가 저장 공간이 부족할 때 정리할 수 있습니다.
같은 이름의 과거 내보내기는 앱이 기록한 자기 소유 URI와 내용 해시로만 재사용합니다.
내용이 다르거나 접근할 수 없으면 기존 항목을 덮어쓰지 않고 새 항목을 생성합니다.
복사 실패·취소 시에는 해당 시도에서 생성한 미완성 항목만 정리합니다.

Android 저장소 설계 근거: [공식 공유 미디어 저장소 안내](https://developer.android.com/training/data-storage/shared/media).

## 파일과 재요청

이 경로의 새 영상 파일명에는 제한된 길이의 포맷 ID를 포함합니다.
이는 다른 화질로 저장한 파일을 현재 요청의 결과로 오인하지 않기 위함입니다.
기존 파일은 이동·삭제·이름 변경하지 않습니다.

같은 포맷을 다시 요청하면 이미 완성된 파일을 재사용할 수 있습니다.
이때는 최종 경로 이벤트와 실제 파일을 확인하며, 파일 수정 시각이 바뀌지
않았다는 이유만으로 실패하지 않습니다. 로그의 완료는 새로운 네트워크
다운로드와 기존 파일 재사용을 모두 포함할 수 있습니다.

## 검증 범위와 제한

- 일반 Android Emulator에서 대상 링크의 기존 엔진 + 로컬 연결 보조 + FFmpeg 조합으로 전체 파일 저장, 영상·음성 메타데이터와 첫 3초 디코딩을 확인했습니다.
- 앱 통합 검증은 파일 생성과 기존 파일 재사용을 구분하여 로컬 검증 결과에 기록합니다. 실제 기기 또는 모든 링크의 성공을 보장하지 않습니다.
- v1.9.25 코드의 앱 통합 검증에서 새 파일 109,182,178바이트, 313.49초, H.264 1920×1080 + AAC를 저장했습니다. MediaStore 내보내기와 SHA-256, 첫 3초 디코딩을 확인했습니다.
- 로그인, 나이 확인, CAPTCHA 등 사용자 확인이 필요한 절차는 사용자가 완료해야 합니다. 인증·접근 권한·DRM을 우회하는 기능은 없습니다.
- 연결 보조를 켜도 네트워크·서버·인증 제한이 모두 해결되는 것은 아닙니다.
- CA와 네이티브 런타임이 변경되지 않은 이번 로컬 빌드에서는 해시가 일치하는 검증된 런타임 AAR 캐시를 재사용했습니다. 런타임을 새로 빌드하는 환경에는 `SOURCE_BUILD.md`의 NDK 등 준비가 필요합니다.
